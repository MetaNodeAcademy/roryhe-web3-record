#### 各层关键模块：

### les（轻节点协议）
LES 是为“轻客户端”设计的 DevP2P 子协议
交互流程：握手 → 同步头 → 按需请求数据+证明 → 本地根据 stateRoot 验证 → 发送交易

### trie（默克尔树实现）
MPT结构：Branch Node、Extension Node、Leaf Node
Geth中用途：世界状态树（State）、交易树（Tx）、收据树（Receipt）、合约存储树（Storage）
Geth针对Trie所做的优化：Patricia、SecureTrie、StackTrie、Pruning

### core/types（区块数据结构）
core/types包，定义了区块、交易、收据的结构以及这些对象如何被哈希、签名、RLP、验证
区块（Block）：header 、transactions 、uncles
交易（Transactions）：LegacyTx、AccessListTx、DynamicFeeTx、BlobTx
收据（Receipt）：Status、Logs、Bloom、CumulativeGasUsed

### 生命周期

应用层（构建签名交易） -> RPC（eth_sendRawTransaction） -> 区块链核心层（校验格式+签名+nonce）-> 存入TxPool  -> 矿工/共识客户端打包交易 -> 区块执行调度 -> EVM执行层（ApplyTransaction/出块）-> 状态存储层（写入状态变更）-> 区块链协议层（P2P广播交易区块）

### 账户状态存储模型
每个账户的数据结构：
```
{
  nonce: uint64,
  balance: uint256,
  storageRoot: hash,
  codeHash: hash
}
```
- 世界状态由 Merkle-Patricia Trie 表示。
- 每个合约账户的 `storageRoot` 指向另一棵存储 trie。
- 所有账户的根哈希 `stateRoot` 存入区块头中。
